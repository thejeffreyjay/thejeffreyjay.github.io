E-Commerce AI Order Assistant for D2C Online Pet Supplies & Retail

Service Represented: AI Agentic Workflows
Platform: n8n (Self-Hosted), Gemini LLM, Webhook, Google Sheets, Google Docs, Slack
Problem: Online store owners and support teams spend significant time answering routine product inquiries and manually processing incoming orders. Without automated validation and stock checks, teams risk fulfilling out-of-stock items or missing customer errors, leading to fulfillment delays and inventory discrepancies.
What I Built: An AI agent workflow that handles conversational customer discovery, real-time inventory lookups, policy retrieval, and two-step order validation. The system connects a customer-facing chat interface to backend validation logic, Google Sheets inventory management, and Slack notifications.
What It Does: It automates product and policy support while enforcing a strict two-step checkout confirmation before processing any order. The system validates customer contact information, checks and updates live inventory levels, logs completed orders into a master spreadsheet, and dispatches real-time alerts to Slack.
What I Found: In testing, an order for 3 units of one item showed 3 in the chat summary but was written to the Orders Masterlist and sent to Slack as 1.
Result: Multi-item orders now show the same quantity in the chat summary, the Orders Masterlist, and the Slack alert. I checked this with 10 test orders.
Changelog

v1.1 (current): updated the Parse Order Code to correctly evaluate the quantity parameter passed by the AI's HTTP payload.

resolution: resolved an issue where multi-item orders were correctly calculated in the chat summary but incorrectly defaulted to 1 when written to Sheets Orders Masterlist and Slack.

v1: initial release with an automated backend webhook pipeline including RAG-based policy lookups, live Sheets inventory tracking, strict phone number regex validation, inventory reduction, Orders Masterlist logging, Slack store alerts and error-handling pipeline.

HOW I HANDLE YOUR DATA

Your data passes through the tools I connect for you. This is how I handle it:

  • I work inside your accounts using only the access required for the build. You can revoke my access at any time.
  • API keys and logins stay in each tool’s connection settings, never in a workflow, chat, or email.
  • Each step gets only the data it needs. I tell you which steps send text to an AI model before I turn them on.
  • Names, emails, and phone numbers are not removed before text reaches an AI model unless we set that up. I can add that step for sensitive data.
  • n8n can run on your own server. The AI model still receives the text it works on.
  • Groq, OpenAI, OpenRouter and Anthropic state they do not train models on API data unless you opt in. Groq and OpenAI may keep API data for up to 30 days to run the service or check for abuse. Make, Zapier, Slack, Airtable, and Cal.com state they have passed SOC 2 audits, and n8n publishes a SOC 3 report.
Note: I am not SOC 2 certified. If your work falls under HIPAA or a similar rule, tell me first so we can check that the tools qualify.
